Tailscale apart instellen

Installeer eerst de actuele Tailscale-client op de bedoelde pc of server. Voer daarna deze regel uit in PowerShell. Geschikt voor Windows 10/11 en Server 2016 of nieuwer, met Windows PowerShell 5.1 of PowerShell 7.

& { $ErrorActionPreference = "Stop"; [Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor 3072; $p = Join-Path $env:TEMP ("jinda-tailscale-" + [guid]::NewGuid().ToString("N") + ".ps1"); iwr "https://raw.githubusercontent.com/acurvers/jinda-operations/main/configure-tailscale.ps1" -UseBasicParsing -OutFile $p -TimeoutSec 60; if ((Get-FileHash -LiteralPath $p -Algorithm SHA256).Hash -ne "5db44d7bf55cd109fd9ccf56c7d16bb9112a21b06496ff0d66954c7c2dab3298") { throw "Checksum mismatch. Copy the current command from the Tailscale webpage." }; powershell.exe -NoProfile -ExecutionPolicy Bypass -File $p }

Het script vraagt zo nodig administratorrechten en stelt in: Tailscale-DNS uit, subnetroutes accepteren uit, geen exit node. Deze voorkeuren worden gecontroleerd.

Als aanmelden nodig is, opent de officiële browseraanmelding. Kies het tailnet van de opdrachtgever. Het script wacht daar niet op. Een bestaande aanmelding blijft behouden; gebruik de Tailscale-app als je bewust naar een ander account wilt wisselen.

Dit losse script installeert geen software en voert geen Windows-inrichting uit. Het is niet voor de Server 2012-machine. Op een beheer-pc die klant-subnetroutes nodig heeft, moet het accepteren van die routes juist aan blijven.
