Tailscale apart instellen

Installeer eerst de actuele Tailscale-client op de bedoelde pc of server. Voer daarna deze regel uit in PowerShell. Geschikt voor Windows 10/11 en Server 2016 of nieuwer, met Windows PowerShell 5.1 of PowerShell 7.

& { $ErrorActionPreference = "Stop"; [Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor 3072; $p = Join-Path $env:TEMP ("jinda-tailscale-" + [guid]::NewGuid().ToString("N") + ".ps1"); iwr "https://raw.githubusercontent.com/acurvers/jinda-operations/main/configure-tailscale.ps1" -UseBasicParsing -OutFile $p -TimeoutSec 60; if ((Get-FileHash -LiteralPath $p -Algorithm SHA256).Hash -ne "4f16be3a1bb289bd20539007416619ecec1371c695f0e8f280ba1449c2b22d76") { throw "Checksum mismatch. Copy the current command from the Tailscale webpage." }; powershell.exe -NoProfile -ExecutionPolicy Bypass -File $p }

Het script vraagt zo nodig administratorrechten en stelt in: Tailscale-DNS uit, subnetroutes accepteren uit, geen exit node. Deze voorkeuren worden gecontroleerd.

Als aanmelden nodig is, opent de officiële browseraanmelding. Kies het bedoelde tailnet; dat mag ook je bestaande tailnet zijn. Het script wacht daar niet op. Een bestaande aanmelding blijft behouden; gebruik de Tailscale-app als je bewust naar een ander account wilt wisselen.

Dit losse script installeert geen software en voert geen Windows-inrichting uit. Het is niet voor de Server 2012-machine. Op een beheer-pc die klant-subnetroutes nodig heeft, moet het accepteren van die routes juist aan blijven.

Andere server als subnetrouter

Wil je vanaf je beheer-pc rechtstreeks naar 192.168.40.13? Meld de tussenserver eerst aan bij je bedoelde tailnet (je bestaande tailnet kan ook). Voer onderstaande opdracht op die tussenserver uit, niet op Server 2012 of je beheer-pc.

& { $ErrorActionPreference = "Stop"; [Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor 3072; $p = Join-Path $env:TEMP ("jinda-tailscale-" + [guid]::NewGuid().ToString("N") + ".ps1"); iwr "https://raw.githubusercontent.com/acurvers/jinda-operations/main/configure-tailscale.ps1" -UseBasicParsing -OutFile $p -TimeoutSec 60; if ((Get-FileHash -LiteralPath $p -Algorithm SHA256).Hash -ne "4f16be3a1bb289bd20539007416619ecec1371c695f0e8f280ba1449c2b22d76") { throw "Checksum mismatch. Copy the current command from the Tailscale webpage." }; powershell.exe -NoProfile -ExecutionPolicy Bypass -File $p -SubnetRouter }

Deze optie voegt alleen 192.168.40.13/32 toe aan de bestaande routeadvertenties. Het script kiest een rechtstreeks aangesloten LAN-adapter en zet IPv4-forwarding aan op die adapter en de Tailscale-adapter, actief en opgeslagen voor na herstart. Het zet Tailscale voor deze server op Run unattended, zodat de verbinding ook zonder aangemelde Windows-gebruiker kan blijven werken. Het herstart geen adapters, services of Windows.

  1. Keur daarna 192.168.40.13/32 goed bij de tussenserver in Machines → Subnets / Edit route settings. Controleer in Access controls wie dit adres mag bereiken binnen je bestaande tailnet.
  2. Zet op je beheer-pc Use Tailscale subnets aan. DNS en exit node mogen uit blijven. Op de tussenserver blijft subnetroutes accepteren uit.
  3. Open Remote Desktop naar 192.168.40.13. RDP moet daar ingeschakeld zijn en Windows Firewall met geavanceerde beveiliging op Server 2012 moet het LAN-IP van de tussenserver toestaan.

Bij meerdere geschikte LAN-adressen: geef -LanIPAddress mee met het LAN-IP van de tussenserver. Controleer na een geplande herstart opnieuw met configure-tailscale.ps1 -VerifySubnetRouter. Die controle past geen netwerkvoorkeuren toe.
